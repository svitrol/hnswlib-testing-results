Outlier queries in HNSW indexes

Experiments on why some queries of HNSW graph indexes need far more distance comparisons than the rest, or miss the true nearest neighbour, compared across three implementations: hnswlib, nmslib and flatnav.

What was done

Data and indexes

Datasets come from ann-benchmarks (HDF5 files with train points, test queries and exact ground truth). For every library I built indexes over the full grid M ∈ {4, 8, 12, 16, 24, 36, 48, 64, 96} × efConstruction ∈ {100, 150, 200, 250, 300, 350, 400, 450, 500} (81 indexes per library and dataset), and queried each with ef ∈ {10, 20, 40, 80, 120, 200, 400, 600, 800}, k = 10. Metric mapping: hnswlib l2 / cosine / ip, nmslib l2 / cosinesimil / negdotprod / jaccard_sparse, flatnav l2 / inner product (normalized vectors for angular data, max. 2·M edges per node). The jaccard datasets are supported only by nmslib. All libraries were compiled in the same Docker image.

What is measured per query

  • comparisons: the number of distance computations of the query (instrumented in all three libraries; flatnav includes its 100 initialization samples).
  • recall@1: a returned point is at least as close as the true nearest neighbour (robust to ties). A query that fails this is a miss.

Variants

  • baseline: the unmodified search.
  • patience: early exit after Patience in Proximity, implemented identically in all three libraries. After each hop, the share of the current top-k that did not change is computed; the search stops after patience consecutive hops with that share ≥ threshold % (counted only once the top-k is full).
  • wc (hnswlib only): the well-connected search. When the search would stop in a local minimum, it continues through a candidate that is at most (alpha − 1)·|bound| worse, provided the candidate's level-0 degree is at least a given fraction of 2·M.

Patience and wc parameters were tuned on the smallest hnswlib index (M = 4, efC = 100; nmslib for the jaccard datasets) over patience ∈ 1–500 × threshold ∈ {70, 80, 90, 100} and alpha ∈ 1.01–1.5 × min degree ∈ {0.5, 0.75, 0.9, 1.0}, then used for every index of the dataset. The selected values are in the table above.

Outliers

Two kinds, analysed separately: comparison outliers, queries above the Tukey fence Q3 + 1.5·IQR of comparisons within one configuration (library, M, efC, ef, variant), and misses. For each configuration it checks which outlier queries all three libraries share and which each pair shares, against the overlap expected if they were independent.

Why hnswlib misses

The saved hnswlib graphs are parsed directly. For every query, the true neighbour t and the returned point r are located in the level-0 graph: BFS from the entry point (reachability) and hop distances to well-connected nodes (top 1 % in-degree, full neighbour lists, nodes on upper levels). Each node's accessibility flags (evaluate_accessibility) are also computed. Every miss gets one reason (see the dataset pages).
